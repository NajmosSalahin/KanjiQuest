## What was built

- **Quiz hub (`/quiz`, §7.5):** five mode cards with 96×96 inline SVG icons (vermillion accent + ink), copy, live counts, and Start actions. Hub data comes from the approved **`GET /quiz/overview`** addition (D15): per-mode `available` + `fallback`, plus the **“practice set”** label when any of the four practice modes is using fallback; **“review queue”** otherwise. Sprint never flips the label on its own.
- **Practice-set service (D15):** tracks `learning` / `review` / `relearning` kanji, filters by mode capability, then fills to **10** from **N5 kanji with stroke order** (shuffled, excluding duplicates). Sprint uses the same fallback with a **40-question** target.
- **Quiz API (§9):** `POST /quiz/start` (201 session + public question(s)), `POST /quiz/:sessionId/answer` (choice, stroke tap, or drawing check), and `POST /quiz/:sessionId/submit` (summary). Sessions are owner-scoped, Zod-validated, and expire after **2 hours**; submit is idempotent through a stored `submitSummary`.
- **Meaning & reading (§6.6 / §7.6):** four options per question; the answer key and distractor generation stay server-side. Reading options are kana rendered inside `<ruby>` with an **On/Kun** `<rt>` label. Every answer is checked by the server; a client retry that arrives after the server advanced is disambiguated by the previous question's option ids (replay returns the stored result, a different option returns `409 QUESTION_ANSWERED`).
- **Stroke order (§6.6 / §7.6):** KanjiVG paths are served as shuffled hit targets; only the next expected stroke counts as correct. A practice wrong tap shakes the stage but does not end the question; a question is correct only with **zero wrong taps**. Numbered chips show progress.
- **Drawing canvas (§7.6 / D14):** pointer input is normalized to the **0–300** box and checked server-side against the KanjiVG template. The geometric scorer samples template paths, computes precision + recall at a 0.075 tolerance, applies a clamped stroke-count factor, and returns **≥85 correct / 60–84 close / <60 not quite**. Two checks maximum; a final miss reveals the template overlay.
- **Sprint (§6.6 / §7.6 / D16):** a 40-question bank cycles meaning, reading, and stroke. The **server owns the clock** (`remainingMs` + `lastTickAt`; client only counts down). Correct answers add **3s**, wrong answers subtract **5s**; a wrong sprint stroke tap ends that question immediately. Submitting before the deadline returns `409 SPRINT_ACTIVE`; a zero-answer sprint returns `422 SPRINT_EMPTY` and earns nothing.
- **XP (D13):** `awardXP(event: 'quiz')` pays **5 XP per correct + 20 completion XP at ≥10 answers** (sprint: **30 base + 10 per correct**). Quiz XP fills the shared `dailyXPProgress` bucket keyed by **`dailyXPDate`**, can add the **+30 daily-goal bonus** once, and never calls the review streak engine. `earn-100xp` reads the same bucket, so quiz-only days progress it.
- **Achievements (D16):** per-question stroke/drawing counters (`perfectStrokeQuestions`, `highDrawingQuestions`), per-session `Kanpeki 完璧` (100% over ≥10 answers) and `Sokko 即交` (20+ correct in 60s), and `Itsutsu 五つ` (each mode completed once) via `quizModesPlayed`. All 41 defs continue to seed/evaluate in one pass.
- **Session UX (§7.6):** full-screen `/quiz/play/:mode` outside the app shell, max-width 640px, 4px progress bar (sprint timer instead), server-confirmed option/stroke feedback, keyboard **1–4**, **Space**, and **`?`** help, a summary card (accuracy, +XP, goal-met chip, sprint best streak), celebration/toast integration, and a **leave guard** for the in-app back button, browser back, and tab close.
- **Data:** new `QuizSession` model (questions, server-only answer keys/templates, per-question result state, sprint clock, stored submit summary) with `{userId, startedAt}` and `{status, expiresAt}` indexes. `GamificationProfile` gains the three quiz counters. `scripts/migrate-070.js` ensures indexes and backfills `dailyXPDate` from `lastActivityDate` for pre-0.7.0 profiles.

## Decisions applied

- **D13** — quiz XP is daily-goal XP, not streak XP; shared `dailyXPDate` bucket; goal bonus once; `earn-100xp` sees quiz XP; migration backfill.
- **D14** — drawing scoring algorithm documented above; server-authoritative geometry with normalized 0–300 client strokes and the §7.6 bands/attempt cap.
- **D15** — tracked practice pool + N5 stroke-capable fallback, `GET /quiz/overview`, and the four-practice-mode “practice set” label.
- **D16** — 10-question practice sessions, strict server order, 2h TTL, ruby reading options, zero-wrong-tap stroke correctness, sprint clock/bank/penalties/submit rules, per-question vs per-session achievement granularity, and the leave guard.
- Open question **#3** (quest-title wording) and **#4** (password reset) remain open; neither blocks Phase 6.
