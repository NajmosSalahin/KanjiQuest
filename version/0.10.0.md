## What was built

- **Installable PWA (D23):** a static `client/public/manifest.json` with the leaf/sprout mark, standalone display, vermillion theme, rice-paper background, and 192/512 plus maskable icons. One SVG source also produced the favicon and 180px Apple touch icon; `index.html` carries the manifest, theme-color, Apple/PWA, canonical, and Open Graph/Twitter tags.
- **Prompt-only updates (D25):** `vite-plugin-pwa` generates the Workbox service worker with an app-shell precache and offline SPA fallback. `main.jsx` registers it through `virtual:pwa-register`, checks hourly for a waiting build, and never reloads automatically. A small “Update available” action appears in the global chrome only after the page settles, while online, with no queued reviews, and on shell routes.
- **Offline reviews (D24):** card ratings from an already-loaded session are queued in IndexedDB (in-memory fallback), scoped by `userId`, with an `eventId` and local `reviewedAt`. Reconnecting flushes oldest-first; the server uses `reviewedAt` for SRS/history and keeps gamification on the profile’s current activity day when a backdated review would rewind it (`timestampAdjusted`). Entries older than 24h are rejected with a summary, duplicate `eventId`s are idempotent, and quiz/store/suspend stay online-only. Undo removes a still-queued event locally; a synced review falls back to the server undo.
- **Server idempotency:** new `ReviewEvent` model with unique `(userId, eventId)` and a 7-day TTL, `migrate-100` indexes, and `reviewedAt`/`eventId` validation inside `POST /progress/review`. A replay returns `duplicate: true`, `awarded: 0`, current totals, and never re-applies XP, history, quests, or streak.
- **Accessibility (§12 / D26):** text-only accessibility tokens (`--text-muted`, `--text-matcha`, `--text-persimmon`) keep the §3 palette for fills/borders while bringing small light-theme text above 4.5:1. Furigana, stroke numbers, chart ticks, rating pressed states, and hard/good button hovers were corrected. `A11Y.md` records contrast measurements, structural checks, and the owner-run NVDA/Narrator checklist.
- **Performance (§13):** every route is lazily loaded, including Dashboard and auth. The app shell and TanStack Query provider are also lazy, and `/login` uses a small controlled form instead of react-hook-form + Zod. After the release hardening, the login route loads the **6.6 kB gzip** entry, the **81.0 kB gzip** React vendor, and only the tiny auth UI chunks — no Query, AppShell, form, validation, chart, or icon-library code. React Query (12.1 kB), AppShell (7.1 kB), and the form stack (23.8 kB) stay behind the auth gate. The main chunk is far under the 200 kB gzip budget; Recharts stays isolated in the lazy Stats route (112 kB gzip) and framer-motion in the lazy celebration chunk (38 kB gzip).
- **Global offline chrome:** an always-visible offline strip shows connectivity and waiting-review count; the global sync hook hydrates XP and invalidates quests/stats/progress/leaderboard after a flush.

## Lighthouse hardening (2026-11-16–17)

The first deployed mobile run scored Performance 61 / Accessibility 92 / Best
Practices 96 / SEO 92. The fixes below are recorded in D28:

- **Fonts:** self-hosted the Latin subsets of Fraunces, Instrument Sans, and
  Geist Mono plus a 1.7 kB `植物` wordmark subset (preloading the first-paint
  faces); the full Noto JP sheets now load only on gated pages, removing the
  render-blocking Google Fonts request and the wordmark's first-paint wait.
- **Auth bootstrap:** a readable `kg_session` hint cookie lets first-time
  visitors go straight to `/login` instead of probing `/users/me` (401) and
  `/auth/refresh` (401). HttpOnly session cookies are unchanged.
- **Vendor/route split:** removed the catch-all `vendor` manual chunk, made the
  app shell and Query provider lazy, and replaced `/login`'s react-hook-form +
  Zod stack with a controlled form. The login route now ships 6.6 kB entry +
  81.0 kB React vendor; Query (12.1 kB), AppShell (7.1 kB), and the form stack
  (23.8 kB) stay off its first paint.
- **Service worker:** registration waits 4 s after load and then yields to
  `requestIdleCallback`, keeping the ~1.4 MB precache off the critical path.
- **Contrast:** added `--text-on-accent` / `--text-on-bright` and applied them
  to every filled accent control; dark-mode white-on-vermillion (3.68:1) is
  fixed while the §3 palette stays unchanged.
- **Structure/SEO:** `<main id="main">` on auth, Review, and QuizSession pages;
  a real `client/public/robots.txt`; per-route canonical URLs instead of the
  root canonical that failed on `/login`.
- **Sign-out hygiene:** `clearServerState()` empties the singleton Query cache
  on sign-out and account deletion, so a second account signing in on the same
  tab never sees the previous learner's cached dashboard or queue.

**Final live Lighthouse (13.6.0 mobile, warmed median of 4): Performance 93.5
(90–94), Accessibility 100, Best Practices 100, SEO 100; FCP 0.8–0.9 s, LCP
0.8–0.9 s, TBT 270–390 ms, CLS 0.** Fresh-deploy runs can be network-cold (the
discarded warm-up scored 82); methodology and outliers are recorded in `A11Y.md`.
