## What was built

- **Seed pipeline (§5.3)** — five-source ingestion into MongoDB: KANJIDIC2 (master list: 13,108 characters with readings, meanings, grade, strokes, frequency, classical radical), KanjiVG (stroke SVGs + component decomposition), kanjiapi (Jōyō 2,140 / Jinmeiyō 863 / per-character JLPT), 214 Kangxi radicals with committed mnemonics (`server/data/radical-mnemonics.json`), JMdict (example words), Tatoeba (example sentences + English translations). Idempotent re-runs; downloads and kanjiapi cached in gitignored `server/.data/`.
- **API (§9, §7.4)** — `GET /kanji` (q, jlpt, strokeCount, radical, joyo, jinmeiyo, page, limit **+ D6: sort, status**), `GET /kanji/:character` (detail: strokes extracted server-side into `{n,d,x,y}` — raw SVG never reaches clients; radicals, components, related kanji), `GET /radicals` (214 pills), `GET /licenses` (§5.8 data). Render-time **kuroshiro furigana as structured tokens** — no `dangerouslySetInnerHTML` anywhere.
- **Client (§7.3, §7.4)** — `/learn`: paged virtualized grid (50/page, never the full dataset), radical pill filter, JLPT tabs, sort control, status filter, 250 ms-debounced search, all spec'd empty states. Kanji detail: big character, **StrokeOrderPlayer** (D5 timings, 0.5× default, vermillion current-stroke highlight, spec'd no-data state), readings with speech buttons (Web Speech API `ja-JP`), example words, sentence with ruby, mnemonic, radicals, related kanji, Add-to-review (honest error toast until Phase 3). `/licenses` page + footer link.

## Coverage report (§5.7, from the seed run)

- 13,108 kanji total — **6,417 with stroke-order SVG**, 5,031 with words, 2,910 with sentences, 2,211 with JLPT, 2,140 Jōyō, 863 Jinmeiyō, 214 radicals.

## Bugs found & fixed during E2E (before shipping)

- KanjiVG zero-padded filename hex (`065e5.svg`) mismatched unpadded KANJIDIC hex (`65e5`) — dropped stroke order for every BMP character; fixed with a canonicalizing loader (`server/src/services/seed/kanjivg.js`).
- Real KanjiVG nests paths in inner groups with matrix-transform number labels — `extractStrokes` returned 0 strokes on all real files; fixed with recursive collection + matrix label parsing (`server/src/services/strokes.js`). Both locked down with regression tests.

## Decisions in this version

- **D6 (approved by owner at §18 review, 2026-10-22)** — `GET /kanji` accepts `sort` (frequency|strokes|jlpt) and `status` (all|learning|mastered) beyond §9's list; `status !== 'all'` returns an empty page until Phase 3 wires real per-user progress.
- Win32 data extraction via system `bzip2 | tar` (no new dependency); list queries via `aggregate()` with nulls-last sentinels; furigana parsed server-side into tokens; Kangxi radicals derived at runtime from Unicode + variant map; word JLPT badges null (no approved source); `--text-kanji-xl/2xl` tokens added verbatim from spec §3; test `launchTimeout` 60 s (slow local device, test infra only).
- Full notes: `DECISIONS.md` § "Implementation notes (Phase 2)".
