## What was built

- **Three-step onboarding (§6.1 / D20):** new accounts land on a non-dismissible modal for JLPT level, daily review pace, and reminder time, with a "Skip for now — use defaults" escape. Finishing or skipping calls the idempotent `POST /users/me/onboarding`, which marks the account complete and bulk-preloads the chosen level (N5 for "Not sure"/skip) into `UserProgress` as `state:new`, due now.
- **Starter queue:** N5 79, N4 166, N3 367 cards; the chosen `dailyReviewLimit` caps the first session at 10/20/40. Preload runs before the completed flag is saved, so a failed bulk write leaves onboarding retryable rather than locking an account out of its starter deck.
- **Legacy-safe flag:** `preferences.onboardingCompleted` has no schema default; registration writes `false` explicitly and any document without the field is treated as complete. `migrate-090` backfills existing accounts.
- **Full password reset (§6.13 / D21):** `POST /auth/forgot-password` returns one generic message for known and unknown emails; `POST /auth/reset-password` consumes a hashed, single-use, 30-minute token, rehashes the password, and revokes every session. New `/forgot-password` and `/reset-password?token=` screens cover request, missing-token, invalid/expired, success, and weak-password states.
- **Brevo email adapter (D21):** production sends through Brevo's HTTPS API with the built-in `fetch` (no new dependency); development/test uses a console driver. Delivery failures are logged without secrets and never change the generic auth response. `render.yaml` sets `EMAIL_PROVIDER=brevo`, `EMAIL_FROM`, `EMAIL_FROM_NAME`, and a dashboard-only `BREVO_API_KEY`.
- **Complete §6.13 settings:** furigana is now the three-state **always / on hover / never** setting (legacy booleans migrate true→`always`, false→`never`), alongside the existing theme, daily goal, review limit, sound, haptics, reminder, JLPT, timezone, avatar, title, and account sections. Auto-save and the "Saved" toast are retained.
- **Global shortcuts + `?` overlay (§6.16):** `?` opens the shortcut reference from anywhere in the shell, `/` focuses Learn search (deep-linked as `/learn?focus=search`), and `g d/l/r/s/p` navigate to Dashboard, Learn, Review, Stats, and Profile. Shortcuts ignore typing targets, modifier chords, open dialogs, and session screens that own their keyboard.
- **Sound + haptics feedback (§11.5):** runtime Web Audio cues for correct, wrong, again, tap, reward, purchase, and undo (no binary assets); Vibration API patterns gated by the haptics preference. Sound defaults on, haptics defaults off, and both are wired into review, quiz, store, and preference changes.
- **Polish audit:** route-level skeleton fallback, skeletons for every async page, compact empty states for dashboard/leaderboard/stats, a retry CTA on the Stats error state, and consistent toasts for preference saves, purchases, reviews, and account actions. No "Loading..." copy remains.
