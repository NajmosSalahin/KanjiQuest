## What was built

- **SRS engine (§10)** — `server/src/services/srs.js`, a pure, clock-injected state machine: standard SM-2 interval growth with the spec's per-rating **ease deltas as the modified EF** (Again −0.20 / Hard −0.15 / Good 0 / Easy +0.15), EF clamped to [1.3, 3.0] everywhere, **minutes** in learning/relearning, **days** in review (a lapse halves the interval in days before re-learn), graduation → `review`, mastery at `interval ≥ 180` (`MASTERED_INTERVAL_DAYS`).
- **`UserProgress` model** — unique `{userId, kanjiId}`, `{userId, dueDate}` compound index for the due queue, `suspendedUntil`/`lastReviewedAt`, and **history capped at the last 100 entries per card** — each entry stores the full previous card state + `xpAwarded` (the snapshot that powers exact undo + exact XP refund). `publicProgress()` projection feeds every response.
- **Review API (§9 + D8/D9)** — `POST /progress/add` (201 / 409 `ALREADY_IN_REVIEW`), `GET /progress/due` (due-first, capped at `preferences.dailyReviewLimit`, joins kanji content incl. example words, excludes suspended, returns `nextDueAt` when empty for §7.2's copy), `POST /progress/review` (SRS + XP + history in one server-authoritative write), `POST /review/:cardId/undo` (**D9**: client enforces the spec'd 4s UX; server accepts ≤ `UNDO_WINDOW_MS` 10s as proxy-latency headroom, else `UNDO_WINDOW_CLOSED`; refunds `xpAwarded` exactly), `POST /review/:cardId/suspend` (7 days, `SUSPEND_DAYS`), `GET /progress/stats`, `DELETE /progress/:character` (**D8**, 204 / 404 `PROGRESS_NOT_FOUND`).
- **Kanji endpoints** — `myProgress` on `GET /kanji/:character` (D8; `null` untracked/anonymous), D6 `status` filter now real (`learning` = tracked-not-mastered — includes new/suspended/lapsed; `mastered` = review + interval ≥ 180), and a new `optionalAuth` middleware so a **stale/invalid token degrades to anonymous** instead of erroring public pages.
- **Thin gamification (§11 subset)** — `server/src/services/xp.js`: review XP +2/+5/+10/+15, first-review-of-day +20 (`lastReviewDate` marker on `GamificationProfile`), daily-goal crossing +30 (once/day by construction), store boost 1.5× applied at award, streak bump. **Undo refunds totalXP/level/dailyXP exactly but never reverts streaks** (monotonic `longestStreak`). Level = accumulated `floor(100 × N^1.5)` (matches Phase 1's level-1 cost). Phase 4 formalizes `awardXP` without changing these response shapes.
- **`/review` screen (§7.2)** — full-screen route outside AppShell behind `RequireAuth`: minimal fixed top bar (back arrow · card counter · `?` shortcuts popover); mobile keeps only the bottom tab bar (`MobileTabBar` extracted from AppShell). 4px vermillion progress bar; card front (6rem `--text-kanji-xl` kanji with furigana `<ruby>` when enabled, full-width/320px "Show answer"); card back (4rem kanji, meanings " · ", On/Kun ruby + 14px speech buttons, example word row, "Remember:" mnemonic); four rating buttons (crimson/persimmon/matcha/indigo, `1`–`4` hints below labels, 220ms fill then card-out), **2×2 on mobile**; keyboard `Space` reveal, `1`–`4` rate, `U` undo, `S` skip (client-side rotation), `X` suspend, `?` help; desktop keyboard footer; bottom-left **4s undo banner** with the previous rating (any other key discards it); session summary card (180px garden SVG, "{n} reviews" / "completed", Accuracy | +XP | Streak, matcha "Daily goal met" banner, Continue + Review again → "All caught up" when empty); "Nothing due" empty state with the scheduled next-review time + Browse kanji CTA; loading skeletons and an error state with retry.
- **Detail wiring (§7.4)** — Add to review (POST + success toast + query refetch) ↔ tracked state ("Learning · next review tomorrow", "Mastered", "buried until …") with secondary Remove (D8 DELETE).
- **Live smoke → 29 checks** — the whole review flow end-to-end against production: add → `myProgress` → due content → review (30 XP first-review + streak 1) → undo (refund 30) → re-review (10 XP, no first bonus) → suspend (excluded from due) → stats → D6 `learning` → D8 204-then-404 → anonymous invariants (`myProgress` null, empty `learning`, `/due` 401). Local runs also delete the throwaway user's `userprogresses`.

## Decisions in this version

- **D8 (owner-approved, Phase 3 plan review 2026-10-28)** — `myProgress` field on `GET /kanji/:character` + `DELETE /progress/:character` for §7.4's "Remove from review", which §9 didn't cover.
- **D9 (owner-approved, same review)** — undo window: the client enforces the spec's 4s (banner expiry + never sends later); the server accepts up to 10s as latency headroom so an in-spec 3.9s click survives the Render proxy. Behavior seen by the user is unchanged.
- History stores a **full previous-state snapshot + `xpAwarded`** (superset of §6.5's four fields — required by the spec's own "compensating transaction" wording and by exact refund); capped at 100/card.
- Undo refunds XP/level/daily exactly; **streaks are never decremented** (a day's activity can't be un-happened).
- **Thin gamification now, `awardXP` in Phase 4** — the review loop is fully playable end-to-end today; XP stays server-authoritative throughout.
- §10 deltas are the SM-2 "modified" EF (formula for growth, deltas for modification — both implemented, both clamped); reps increment on review success, graduation sets reps 1.
- D6 semantics: `learning` = any tracked pair that is not mastered (incl. `new`), `mastered` = `review && interval ≥ 180`; anonymous → empty for both.
- `optionalAuth` (stale tokens degrade to anonymous); `nextDueAt` additive field for the empty state; `/review` chrome lives outside AppShell (mobile keeps only the bottom tab bar per §7.2); skip/suspend are keyboard-only because §7.2 specifies no touch controls for them.
- Full notes: `DECISIONS.md` § "Implementation notes (Phase 3 — SRS review system)"; D-ids mirrored in `IMPLEMENTATION_PLAN.md` §3.
