## What was built

- **`awardXP` formalized (§11.1)** — `server/src/services/xp.js` becomes the single XP event router: review XP with the **1.5× boost applied to all XP**, one level recompute through `computeLevel`, achievement evaluation in the same pass, and a returned snapshot (`newlyUnlocked`, `streakMilestone`, `leveledUp` + previous level/title, profile counters) that `refundReviewXP` restores exactly on undo — achievement unlocks themselves are permanent. Extended progress history (`history<void>`/`gami`) so undo restores the Phase 4 counters byte-for-byte while XP refunds stay exact and streaks never revert.
- **Streak engine (§11.4) — `services/streak.js` + `services/time.js`**: timezone-correct increment/reset (`localDay`/`dayDiff`), break-corrected display streak, milestone crossing (7/30/100) + `nextMilestone` labels (**Wakaba 14 · Sakura 30 · Hanami 60 · Momiji 100**), the freeze consumption rule (one freeze per missed day, consumed only when `streakFreezes >= missedDays` — store grants arrive Phase 7), and the approved **D10** `POST /gamification/streak/repair` (**100 coins**, previous-local-day breaks only, once per calendar month, 409s otherwise; sets `lastActivityDate = yesterday` so the next review chains).
- **Achievements (§6.6 / §11.3) — D11 roster of 41**: the spec's 23 after Q4's social-pair removal, with Japanese names (romaji + 漢字/かな, `N5 Kansei`-style) plus **18 owner-approved additions** (easy/mid/late milestones, N3/N2/N1 completion, level goals, counter quests, quiz/quest/freeze criteria), each with the rewards approved in the Phase 4 conversation. `server/src/scripts/seed-achievements.js` upserts into the `achievements` collection (§8 structured criteria); `aggregateLearningSignals` runs one `$facet` only when a locked def actually needs it; cheap criteria read the new profile counters; quiz/quest/freeze types ship dormant and return `progress: null` (unlock when Phases 5–7 land, no migration); **Zenshū 全集** unlocks in the same pass at **32 of the other 40**.
- **Gamification endpoints (§9)**: `GET /gamification/profile` — break-corrected streak, rolling 7-day grid (aggregated from review history in the user's timezone), `nextMilestone`, repair state, level/title/coins, `achievements: { unlocked, total }`; `GET /gamification/achievements` — self-seeding, `unlocked`/`unlockedAt`/`progress` per def; `POST /gamification/streak/repair` (D10).
- **Dashboard §7.1 (minus quests + mini-leaderboard)** — header (rank + level XP, streak + title, daily goal, coins, date, repair toasts), exact-copy repair banner (dismissible), streak card (5-tier `StreakLeaf`, Monday-anchored `M T W T F S S` dot grid over the server's rolling 7 days, milestone bar), daily-goal `GoalRing` + "Goal met" matcha state, due card ("Start review" / "All caught up — next review at HH:MM"), empty state deep-linking to `/learn?jlpt=5`. Learn now honors the `?jlpt=` query param.
- **Celebrations (§11.2 / §11.4)** — `CelebrationModal` (Radix + framer-motion, approved §3.8, custom garden-stage SVG) for level-ups and streak milestones **7/30/100**, which **fold in their own achievement's toast**; every other unlock fires a compact toast with name + rewards (41 two-color hand-drawn `AchievementIcon`s, 1.5px, 24×24). In `/review` the modal is deferred to the **summary screen** so the card rhythm is never interrupted mid-card; the dashboard fires toasts immediately after its repair action.
- **§11.6 correction (not a deviation)** — `dailyGoalXP` **default 50** with options **20/50/100/200** (Phase 1 shipped default 100 / enum `[50,100,200]`, missing 20). Both schemas now derive from shared `DAILY_GOAL_OPTIONS` / `DEFAULT_DAILY_GOAL_XP`; `server/src/scripts/migrate-050.js` flips every stored 100 → 50 (owner-approved, no settings UI ever existed, blanket-safe); `PATCH /users/me/preferences` mirrors goal changes onto the profile, and reviews read from the profile mirror.
- **Data model** — new `Achievement` collection; `GamificationProfile` gains `streakFreezes`, `goalStreak`/`goalMetDate`, `currentPerfectRun`, `dailyReviewsCount`/`dailyAgainToday` + `dailyCountersDate`, `reviewsBefore8`/`reviewsAfter23`, `lastStreakRepairAt`, and `achievementUnlocks` (id → Date, pointer into §6.10's profile tab; `unlockedAchievementIds` stays the §8-canonical list). `User.preferences.dailyGoalXP` carries the [20,50,100,200] enum.
- **Live data ops** — ran `npm run migrate-050 -w server` (1 user + 1 profile flipped 100→50) and `npm run seed-achievements -w server` (41 defs, 41 upserted) against the shared Atlas instance that Render also serves. No schema migration needed for existing unlocked achievements (permanent, additive criteria).
