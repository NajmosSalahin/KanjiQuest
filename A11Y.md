# Accessibility report (WCAG 2.1 AA)

Kanji Garden v0.10.0 · Phase 9 · last updated 2026-11-18

This document records the Phase 9 accessibility audit against `prompt.md` §12 and
§5.9. It covers automated contrast measurements, structural/manual checks, the
fixes that shipped, and the owner-run screen-reader checklist. The owner declined
the checklist on 2026-11-18 (D30); the report is otherwise final.

## Standard and scope

- Target: **WCAG 2.1 AA** — body text ≥ 4.5:1, large text ≥ 3:1, visible focus
  on every interactive element, no color-only signals, keyboard operability.
- Screens audited: dashboard, review session (front/back/empty/summary), kanji
  detail, quiz session, Learn, Stats, profile/settings, store, leaderboard,
  onboarding, auth, and the global chrome (nav, mobile tabs, toasts, offline
  banner, PWA update action).
- Assistive technology: NVDA 2026 + Firefox/Chrome on Windows (owner run);
  Narrator + Edge as the secondary pass.

tokens so the §3 fills, borders, and illustrations keep their specified colors.
All ratios below were calculated with the WCAG relative-luminance formula.

| `--text-matcha`     | `#435331` | 7.86:1              | 8.40:1               | 7.20:1              |
| `--text-persimmon`  | `#8d5123` | 5.93:1              | 6.33:1               | 5.43:1              |

Filled-control combinations. `--text-on-accent` is white in light mode and

The dark-mode text tokens (`--text-muted`, `--text-matcha`,
`--text-persimmon`) resolve to the §3 dark values, which already clear 4.5:1
on the dark surfaces.

### Fixes applied

- Added text-only tokens `--text-muted`, `--text-matcha`, and
  `--text-persimmon`; Tailwind `textColor` maps `text-ink-muted`, `text-matcha`,
  and `text-persimmon` to them. Fills, borders, icons, charts, and SVG artwork
  still use the §3 palette tokens.
- Furigana (`ruby rt`), stroke-order numbers, and Recharts axis tick labels now
  use `--text-muted` instead of the 3.4:1 `--ink-muted`.
- Added `--text-on-accent` (white in light, dark ink in dark) and
  `--text-on-bright` (dark ink in both). They replace every white-on-fill
  label: primary buttons, rating fills, selected onboarding chips, the avatar
  edit button, quiz option fills, and the PWA update action. The 10px rating
  shortcut label now uses a solid token instead of `text-white/80`.
- Rating buttons: Hard/Good use `--text-on-bright`; Again/Easy use
  `--text-on-accent`. Button variants `hard` and `good` follow the same rule.
- Offline banner, sync toast, and PWA update action use `role="status"` /
  `aria-live="polite"` and never steal focus.

### Automated tooling

- `npm run lint` — clean (core ESLint; no React/a11y plugins by decision).
- Component tests exercise landmark names, labels, live regions, keyboard
  review flow, the offline queue, and the session-hint bootstrap (110 client tests at release).
- Lighthouse mobile (accessibility category) is run against the deployed
  client as part of the Phase 9 release; the score is recorded below.

| Lighthouse mobile run                         | Performance        | Accessibility | Best practices | SEO |
| --------------------------------------------- | ------------------ | ------------- | -------------- | --- |
| Deployed client, Phase 9 (warmed median, n=4) | 93.5 (range 90–94) | 100           | 100            | 100 |

Lighthouse 13.6.0 mobile (`--throttling-method=simulate`, Moto G Power, 4× CPU)
against `https://kanjiquest.vercel.app/login` after the CDN was warm. One
discarded warm-up run scored 82 while the network settled; the four measured
runs scored 94 / 94 / 93 / 90 (median 93.5), with FCP 0.8–0.9 s, LCP 0.8–0.9 s,
TBT 270–390 ms, and CLS 0. Runs taken immediately after a fresh Vercel deployment
can be network-cold (earlier runs on the pre-final build scored 75/80 with the
entry JS starting around 2.3 s); those are environment variance, not app work.
§13 budgets: FCP < 1.8 s, main JS chunk 6.6 kB gzip (limit 200 kB), React
vendor 81.0 kB gzip.

## Owner screen-reader checklist (NVDA/Narrator)

**Status (2026-11-18):** the owner declined this pass (D30). §12's
screen-reader requirement is recorded as an accepted limitation — **not
performed**, not a pass. The checklist is retained for a future re-audit.

Run once in NVDA + Firefox or Chrome at desktop width, then spot-check Narrator

- Edge. Report only failures and confusing announcements; "pass" is the default
  when the reading matches the expected copy.

### 1. Dashboard (`/`)

1. Tab from the address bar: the first stop should be **Skip to content**;
   Enter moves focus to `<main>`.
2. Landmark list (`D` in NVDA) should expose banner, navigation (Sections),
   main, and contentinfo.
3. Headings should announce "Today" as the page heading, then the daily-goal,
   quests, and recent-review sections in visual order.
4. Streak pill: the number is followed by "day streak"; the 7-day grid should
   not read seven unlabeled dots (decorative).
5. Daily goal: ring exposes "XP", the numeric progress, and "Goal met" only when
   completed.
6. Quests: each row reads title, description, progress, and reward; completed
   rows say completed and are not actionable.
7. Offline check: turn Wi-Fi off, reload. The banner should read "Offline —
   reviews will sync when you reconnect" without moving focus.

### 2. Review session (`/review`)

1. The counter reads "Card 1 of N"; the kanji front is announced once, with
   furigana only when it is visible.
2. Space reveals the answer; focus stays on the page, and the back content
   reads meanings, On/Kun labels, readings, example word, and mnemonic.
3. Tab reaches all four rating buttons; each reads its label and shortcut.
4. Press 3 (Good). The next card advances and the undo banner announces
   "Rated Good" plus the Undo button.
5. Press U. The previous card returns to the front and XP is restored.
6. Rate the last card. The summary reads review count, accuracy, XP, streak,
   and the Continue/Review again buttons.
7. Offline check: disconnect, rate a card. The toast announces it was saved
   offline and the summary mentions pending offline reviews.

### 3. Kanji detail (`/kanji/水`)

1. The page heading includes the kanji character and its primary meaning.
2. Back link reads "Back to Learn"; stroke count and radical are in one
   readable row.
3. Stroke-order controls: Play/Pause, speed toggle, and Reset each have names;
   the SVG is not a focus stop and does not dump path data.
4. On/Kun reading chips and speaker buttons read "Play reading …" with the
   Japanese reading.
5. Example words read word, reading, meaning, and JLPT badge; audio buttons are
   labeled.
6. Add/remove review action reflects the current state and announces changes.
